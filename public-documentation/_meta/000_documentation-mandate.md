# Public Documentation Mandate

Phase I public documentation exists to explain SCR's architecture to technically sophisticated readers without becoming a second normative semantic specification.

## Objectives

The public documentation must:

1. explain what SCR is;
2. explain why semantic computation is its central concern;
3. explain how the architecture fits together;
4. provide concrete examples;
5. distinguish architecture from implementation;
6. expose research questions honestly;
7. provide traceability into the repository.

## Authority

Public documentation is explanatory.

Normative semantic definitions live in the semantic library and project specifications.

## Required discipline

Every document should avoid implying that a proposed architecture is implemented merely because it is described.

Use the shared status vocabulary:

- Established
- Implemented
- Experimental
- Specified
- Proposed
- Research
- Illustrative

## Audience

Primary audiences are:

- compiler engineers;
- systems engineers;
- researchers;
- simulation and scientific-computing practitioners;
- infrastructure architects;
- developers evaluating SCR.

## Phase I principle

The documentation should make the architecture understandable before attempting to document every subsystem.
