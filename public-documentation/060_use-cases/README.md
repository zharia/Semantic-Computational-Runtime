# SCR Use Cases and Market Segments

## Purpose

This directory replaces and extends the previous SCR use-case documentation with a cohesive portfolio of use cases and target market segments.

The documents are deliberately written from the Semantic Field outward. SCR is not positioned as a collection of replacements for databases, brokers, workflow engines, model servers, or hypervisors. Those technologies are treated as specialised physical or runtime manifestations of a more general semantic computational substrate.

## Common structure

Each use-case document addresses:

1. What the domain does.
2. Problems and friction encountered by conventional platforms.
3. Key technical and operational requirements.
4. What SCR can offer.
5. How the Semantic Field changes the architecture.
6. The non-obvious advantage obtained by deploying SCR.
7. Competitive positioning and limitations.
8. Target users and adoption opportunities.
9. A credible adoption path.

## Positioning thesis

SCR's strongest claim is not that it will beat every specialist system at a narrow benchmark. The stronger and more defensible proposition is that specialist systems force applications to repeatedly translate between data, state, computation, topology, resources and representations.

SCR seeks to preserve semantic identity while allowing representation, placement, execution mechanism and physical manifestation to change. The resulting optimisation boundary is therefore the whole computational topology rather than an isolated component.

> **SCR is a semantic computational substrate in which computation is the transformation of semantic structure and physical execution is its manifestation.**

## Architectural basis

The portfolio assumes the current SCR architecture:

- Semantic Field primacy.
- Entities, relationships, transformations, context, state, constraints and manifestations as first-class concepts.
- Execution as evolution of semantic topology.
- Representation independence.
- Relationship and transformation primacy.
- Topological mutability.
- Resource separation.
- Semantic identity persisting across physical relocation.
- Whole-system optimisation across memory, compute, storage and network.
- Distribution as a manifestation of field structure.
- Virtual machines as nested computational fields.

These use cases are therefore market-facing applications of the same computational model rather than independent product concepts.
