## 1. Executive Summary

This report formalizes the normative amendments to the foundational **IAM-001 Identity Address Space Model specification**, officially advancing the specification from **Version 0.1 to Version 0.2**.

These amendments codify the architectural discoveries, counterexample resolutions, and empirical evidence generated by the executable reference machine (IAM-RM-001) during Sprints 002 and 003. All amendments preserve the core principle of coordinate abstraction: **concrete SID encodings (e.g. 128-bit width, bitmask fields, or embedded timestamps) are strictly deferred to SID-001**.

## 3. Normative Amendment Texts

### Amendment 1: Snapshot Historical Consistency
```markdown
### Rule IAM-R017: Snapshot Historical Consistency (Normative)
Snapshot recovery MUST NOT produce a state in which a Semantic Identifier exists in 
historical allocation state (H) without the corresponding historical structures required 
to establish its allocation provenance (P) and domain membership (D). If binding (B) 
or manifestation (M) history existed before snapshot or crash recovery, recovery must 
preserve the corresponding state according to semantic lifecycle rules.
```

### Amendment 2: Transaction Immutability & Non-Rebinding
```markdown
### Rule IAM-R018: Transaction Immutability (Normative)
A transaction identifier MUST NOT be rebound to a different SID after its first committed 
association. A retry of an existing transaction identifier with its original SID parameters 
MUST evaluate to idempotent success. Any attempt to associate an existing transaction 
identifier with a new or different SID MUST be rejected unconditionally.
```

### Amendment 3: Multi-Root Scoped Identity Boundary
```markdown
### Rule IAM-R019: Multi-Root Scoped Identity (Normative)
SCR supports multiple independent root authorities. Across autonomous roots, global 
identity is defined by the context pair GlobalIdentity = (Root, SID). Equality of local 
SID coordinates across distinct roots does NOT imply semantic identity equivalence:
  (SID_A == SID_B) ∧ (Root_A != Root_B) ⟹ Identity_A != Identity_B
The Root authority identifier MUST remain external context and MUST NOT be embedded 
into the physical representation of the SID coordinate.
```

### Amendment 4: Deterministic Derived Allocation Constraints
```markdown
### Rule IAM-R020: Derived Allocation Constraints (Normative)
A deterministic function SID = F(parent, local_id) is NOT an allocation authority. 
A domain authority may authorize derived allocation if and only if:
1. F(k) ∈ D.region (Domain containment)
2. F(k_1) == F(k_2) ⟹ k_1 == k_2 (Local injectivity)
3. F(k) ∉ H (Historical non-collision)
A derived coordinate remains an uncommitted candidate until an authorized domain transition 
commits it into H and P.
```

## 4. Strict Negative Invariant: Preservation of Coordinate Abstraction

> [!CAUTION]
> **No Premature Physical Encoding in IAM-001 v0.2.**
> 
> IAM-001 v0.2 strictly maintains the coordinate geometry as an abstract topological space:
> - Concrete bit width (e.g. 128-bit vs 256-bit) is NOT locked.
> - Specific bit field layouts and prefixes are NOT defined.
> - Timestamps, generations, and cryptographic signatures are NOT embedded in the coordinate.
> - External identifier formats (UUID, ULID, Snowflake) are NOT adopted.
> 
> Physical coordinate representation belongs exclusively to the downstream specification **SID-001**.
