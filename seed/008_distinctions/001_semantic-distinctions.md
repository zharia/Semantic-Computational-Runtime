# Canonical Semantic Distinctions

These distinctions are anti-collapse constraints for agents and implementers.

| Distinction | Meaning |
|---|---|
| Semantic Entity ≠ Representation | A semantic object can have multiple representations. |
| Identity ≠ Storage Identity | Semantic persistence is not tied to memory or database identity. |
| State ≠ Storage | State is semantic configuration; storage is one realization. |
| Relationship ≠ Pointer | A pointer may realize a relationship but does not define it. |
| Geometry ≠ Topology | Metric structure and structural connectivity are distinct. |
| Morphology ≠ Mesh | A mesh is one representation of form, not the meaning of morphology. |
| Information ≠ Data | Data can carry information without being identical to its meaning. |
| Provider ≠ Semantic Authority | Providers implement contracts. |
| Execution ≠ Meaning | Execution realizes semantic intent. |
| Observation ≠ Rendering | Observation is information acquisition; rendering is manifestation. |
| Semantic Field ≠ Hypergraph | A hypergraph can represent field structure but is not the field itself. |
| Semantic Type ≠ Implementation Class | A type carries semantic meaning and constraints, not merely code structure. |
| Constraint ≠ Implementation Check | A semantic constraint may be realized by many verification mechanisms. |
| Capability ≠ Hardware Feature | A semantic capability may be realized on multiple substrates. |
